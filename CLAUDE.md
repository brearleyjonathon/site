# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page static portfolio. Markdown in `content/` is rendered by `build.py` (one file, standard library only, Python 3.8+) into `dist/`. There is no package manager, no test suite, and no linter. `dist/` is gitignored and must never be committed.

## Commands

```bash
python3 build.py            # build into dist/
python3 build.py --serve    # build, then serve at http://localhost:8000
python3 build.py --serve --port 8001
```

The in-app preview config (`.claude/launch.json`) is named `portfolio` and runs the serve command on port 8000.

Deployment is automatic: pushing to `main` runs `.github/workflows/deploy.yml`, which builds with Python 3.12 and publishes `dist/` to GitHub Pages.

## Architecture

**Pipeline** (all in `build.py`, top to bottom): `split_frontmatter` → `render_markdown` (block level) → `render_inline` (spans) → `build` (template substitution, copy assets) → `serve` (optional dev server).

**Content model**
- `content/_site.md` holds site settings as a `key: value` frontmatter block only (name, title, tagline, description, url, lang, default_theme, default_font, footer). Any file starting with `_` is skipped as a section.
- Every other `*.md` in `content/` becomes one `<section>` on the page, in filename order. The section `id` is the filename with the numeric prefix stripped (`01-about.md` → `#about`). Sections that render to nothing are dropped.
- Headings in content files are demoted by one level, so `#` in a file becomes `<h2>` (the page `<h1>` is the site name).

**Custom Markdown parser, not a library.** Only the following is supported: headings, paragraphs, `-`/`*`/`+` bullets, numbered lists, blockquotes, `---` rules, inline code, links, bold, italic. No fenced code blocks, images, tables, or nested lists. If a content change "doesn't render", check whether the syntax is in this list before touching the parser.
- ` :: ` inside a list item splits it into `.item-main` / `.item-meta` (right-aligned). When *every* item in a list uses `::`, the list gets `class="rows"` and loses its bullets; otherwise it is a normal list. This is what makes the CV and writing lists align.
- Inline rendering escapes HTML first, stashes code spans and URLs, then applies `--` → en dash and `...` → ellipsis, so those substitutions never touch code or links. External links get `target="_blank" rel="noopener noreferrer"`.
- Wrapped continuation lines (indented or not) are joined into the item above; a blank line ends a list only if the next non-blank line is not another item.

**Template.** `templates/base.html` is plain HTML with `{{placeholder}}` tokens replaced by string substitution in `build()`. Adding a new site setting means adding both a `{{token}}` in the template and a `page.replace(...)` line in `build()`. `{{tagline}}` and `{{footer}}` are rendered through `render_inline`, so they accept inline Markdown.

**Theme and font.** An inline script in `<head>` sets `data-theme` (`light`, `dark`, `fun`) and `data-font` (`sans`, `serif`) on `<html>` before first paint from localStorage, falling back to the `_site.md` defaults (`auto` follows the OS). `assets/style.css` keys everything off those two attributes via CSS custom properties, and includes a print stylesheet.

- The two typefaces share one declared `--step` and `--leading`; the serif is matched to the sans optically with `font-size-adjust` (`--x-height`) so switching does not reflow the page. A `@supports` block restores the old manual size bump where `font-size-adjust` is missing.
- `data-theme="fun"` keeps the black-on-white tokens and adds five `.blob` elements inside `.blobs`: wide, soft pools of one colour each, overlapping on a `--base` of their average so the field reads as one blended gradient rather than blobs on white. They are attractor points moved by `assets/app.js`, not by CSS, each on a slow Lissajous path read from one shared clock. Scrolling winds that clock forward, up to about ten times its resting rate, and it decays back. Because the field never stops moving, the animation loop runs continuously while Fun is on; `requestAnimationFrame` stops it when the tab is hidden. Their colours come from `--c1`..`--c5`, which `assets/app.js` writes as one anchor hue and two neighbours either side (18° apart, converted from OKLCH so lightness is even round the wheel); `--base` is the same hue, pale. The hue starts from the time of day (`HOURS`, one hue per anchor) and turns slowly as the pointer travels (`SPIN`, degrees per px), so the field is always one analogous family and never averages to grey. A pill sub-switch beside the theme buttons (`.fun-controls` inside `.theme-group`, slid in only in Fun, state in `data-fun` on `<html>` and localStorage `fun-mode`, old value `cursor` read as `source`) picks between `field`, where the pools show and the pointer clears them to white, and `source`, where the page stays white and the pointer lays the colour down; each trail mark remembers the hue it was made in. The pools sit in a `.pools` wrapper clipped to a circle centred on the last switch button pressed (`--px`/`--py`, set on click), wider than the screen in `field` and zero in `source`, and the clip transitions, so the colour visibly gathers into the button or blooms out of it. The pressed side is marked by a `.thumb` under the buttons painted with the live `--c1`/`--c3`/`--c5` gradient; `seat()` in `assets/app.js` measures the pressed button into `--tx`/`--tw` (and the old position into `--fx`/`--fw`) and, on a switch, adds `.hop`, whose keyframes first draw the thumb in to a circle where it is, then carry the circle across (stretching on the way), and only then open it out into the other side. A `.trail` canvas sits inside `.blobs`, above the pools. Each clearing is a mark in a list, not a mark burned into the canvas, because it has to keep opening out after it is made: every frame the canvas is cleared and each live mark is redrawn larger and fainter than the frame before. White there cancels the colour because the page beneath is white. The clearing is one pre-rendered sprite whose edge runs through a seven-stop ramp, scaled per mark, rather than a gradient rebuilt per draw.
- The `.shard`, `.diver`, `.splash`, `.flicks`, `.drop` and `.swimmer` rules sit after the warp, deliberately. They used to sit between the blob rules and the grain, where two separate rewrites of the field section swept them away without any error: the words still got wrapped and the figure still got built, they simply had no `position` or animation left, so nothing moved. Keep them below the field, and after changing that section check that a word actually shifts rather than that the spans exist. A click sends a small doodled animal off the pointer: it hops, cross-fades from standing to tucked, spins once and falls all the way to the bottom of the window, landing bottom-first; the landing draws a wavy water line outward from the point of impact and throws up splash strokes and droplets. The flight time (`--flight`, set inline per dive) grows with the distance to fall, and the splash animations are delayed by the same variable. Clicks take turns through ten animals (bear, cat, rabbit, frog, duck, elephant, camel, giraffe, penguin, hippo); six share one body and differ only in the face, the other four have their own shapes in `SHAPES`, all SVG paths in `assets/app.js` with every `stroke-width` scaled by `THIN` when the SVG is built. The strokes are roughened by the `#ink-sketch` turbulence filter defined once in the template's `.filters` svg and applied in CSS to the `.ink` group, so they read as pencil; the timing is CSS keyframes in `assets/style.css`. Each dive carries a `--size` that scales the figure and, later, its swimmer; it is fixed at 1 (a jitter was tried and taken out). Half a second after landing the animal surfaces as a `.swimmer` fixed along the bottom of the window, centred on where it landed and kept just inside the sides, backed by a solid shape in `--bg` (`BACKS`, one per float silhouette) so the one in front hides the one behind; with `data-font="sans"` `lineUp()` instead arranges them in a row from the left in landing order (the serif leaves them where they landed), and a face change slides them between the two arrangements; it stays there, and only when more than forty are afloat does the oldest slip away. They are cleared when Fun is switched off, and hidden in print. Every word in `main` is also wrapped in a `.shard` span while Fun is on and unwrapped when it is off; words near the pointer, and near any animal still in the air (`flying`, polled each frame while any is up), are nudged aside with `left` / `top` and eased back by a CSS transition. The pill keeps its thin CSS border; outside it the `.pill-line` svg holds one scalloped path traced about three quarters of the way round the perimeter by `outline()` in `assets/app.js` (a wave along the normal, an integer number of bumps), redrawn each frame from `step()` with the wave phase and the start of the gap both advancing, so the line visibly travels round the pill (a lap every nine seconds).
- The shards stay `display: inline` deliberately. `inline-block` would allow transforms and so rotation, but a browser may break a line between two atomic inlines even with a word joiner between them, which orphaned the punctuation after a link onto its own line. A relative offset moves an inline box without touching layout or line breaking. Positions are measured once, while nothing is displaced, and re-measured on resize and on a `data-font` change. Grain (`body::after`) and a displacement filter on `main` sit over the top. None of it prints, and the moving parts sit out under `prefers-reduced-motion`.
- The blob animation is named `blob-drift`. If the blobs ever sit still, check that its `@keyframes` block still exists; an earlier edit to this section deleted it while leaving the `animation` shorthand in place, and nothing warns about a missing keyframe name.

**Dev server.** `serve()` has no file watcher. On each request for `/` it compares the newest mtime under `content/`, `templates/`, and `assets/` to the last build time and rebuilds if newer. Changes to `build.py` itself require restarting the server. Assets are copied flat into `dist/` (no subdirectories), and a `.nojekyll` file is written so GitHub Pages serves the output verbatim.
