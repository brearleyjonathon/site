# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static portfolio: one home page plus a page per project. Markdown in `content/` is rendered by `build.py` (one file, standard library only, Python 3.8+) into `dist/`. There is no package manager, no test suite, and no linter. `dist/` is gitignored and must never be committed.

## Commands

```bash
python3 build.py            # build into dist/
python3 build.py --serve    # build, then serve at http://localhost:8000
python3 build.py --serve --port 8001
```

The in-app preview config (`.claude/launch.json`) is named `portfolio` and runs the serve command on port 8000.

Deployment is automatic: pushing to `main` runs `.github/workflows/deploy.yml`, which builds with Python 3.12 and publishes `dist/` to GitHub Pages.

## Architecture

**Pipeline** (all in `build.py`, top to bottom): `split_frontmatter` → `render_markdown` (block level) → `render_inline` (spans) → `build` (template substitution, copy assets) → `serve` (optional dev server).

**Content model**
- `content/_site.md` holds site settings as a `key: value` frontmatter block only (name, title, tagline, description, url, lang, default_theme, default_font, footer). Any file starting with `_` is skipped as a section.
- Every other `*.md` in `content/` becomes one `<section>` on the page, in filename order. The section `id` is the filename with the numeric prefix stripped (`01-about.md` → `#about`). Sections that render to nothing are dropped.
- Headings in content files are demoted by one level, so `#` in a file becomes `<h2>` (the page `<h1>` is the site name).
- The sections now are `01-about`, `02-work` (publications, the thesis, studio projects, smalls, lectures, exhibitions, in that order: Jon's choice, so the professional work leads; the thesis has a one-item list of its own because it sits between research and design), `03-cv` (heading "Experience": work, service, education), `04-slop` (side projects) and `05-contact` (heading "Elsewhere"). Titles in the list sections are bold: `**Title**, …` in work and CV, and `[**Title**](url)` where the title is itself the link (projects, education, slop).
- **Project pages.** Each folder in `content/projects/` with an `index.md` becomes a page at `/<folder>/` (`dist/<folder>/index.html`), and every other file in the folder is copied beside it, so images are linked by bare filename. `index.md` takes `title`, `date`, `credit` and `description` frontmatter; the build writes the title (as the `<h2>`), the date under it and the credit under that (school, studio or instructor, collaborators; inline Markdown, so it can link), so the body starts straight in with content and has no title heading of its own. The body is rendered into one `<article class="section project">`. Nothing lists projects automatically: each is linked by hand from the Studio or Smalls list in `02-work.md` as `[**Title**](folder/), a short description :: year`, newest first. Studio holds the design projects, collaborations among them (Deep Cut, Village Square Pavilion, Graphic Precarity, Anthropocene); Smalls the shorter pieces (Moynihan Train Hall, Additive Timber, The People's Pool, Chair, Reassemble, Portland Wall). Exhibitions entries link to the project page where there is one (Part Objects to Graphic Precarity, Anthropocene, Extracurricular PSU to Portland Wall). The folder names match the old Adobe Portfolio URLs (`brearleyjonathon.com/accommodations`), even where the title has changed since (`deconstructed-theater` is Particle Theater, `on-being-and-void` is Funerary Landscape).
- **Importing from the archive.** The old site is archived at `C:\Users\brear\Claude\Projects\brearleyjonathon-website\`, one folder per project with the original `text.md`, `page.html` and full-size images; `INDEX.md` there lists them by old section (Projects, which the old site called Studio, Collaborations, Smalls). `python tools/import_project.py <archive folder>` drafts `content/projects/<folder>/`: it reads the old layout from `page.html` so pairs and grids come out as rows, drops the second copy the export saved of every pair, and resizes the images (WebP, 1800px wide at most, 1200px for animations, flattened onto white). It needs Pillow; the build does not. The draft still needs a person: alt text for every image, a `description`, the date without its comma, headings for the old all-caps labels, and blank lines where the old site kept separate lines (the parser joins consecutive lines into one paragraph).
- **The edit.** An imported page is the whole old page, and that is too much: the Studio pages were then cut down, with Jon choosing, to the 4 to 11 images that explain each project (renderings, one key diagram, a plan or section), dropping research boards, site photos, precedents and repeats. Text that described cut images was folded into the prose (Safest's six phase panels became a numbered list; Particle Theater's three performance narratives were shortened). Cut files are deleted from the folder; the archive keeps them. Kept images were then cropped: empty margins trimmed to a small border (`margin_box`-style, from the corner colour), and board furniture (titles, legends, key plans, text that repeats the page) cut by hand. Don't trim renderings whose edge colour is part of the picture, such as a night sky. Pages come out at 1 to 3 MB, Particle Theater at 7 MB with its one video.
- **Videos** on the old site were Adobe embeds. They were fetched as MP4s into the archive as `video-NN.mp4`, and the importer copies them. To fetch another: the embed URL in `page.html` (`www-ccv.adobe.io/v1/player/ccv/<id>/embed?...`) returns a page whose `cdn-prod-ccv.adobe.com/<id>/rend/<id>_720.mp4?hdnts=...` link (576 for some) downloads with its token for a few days. Anthropocene's and Reassemble's were fetched this way in September 2026. Nothing on this machine can pull frames from a video (no ffmpeg; headless Edge hangs on video), so their labels are plain until Jon describes them.

**Custom Markdown parser, not a library.** Only the following is supported: headings, paragraphs, `-`/`*`/`+` bullets, numbered lists, blockquotes, `---` rules, images on a line of their own, inline code, links, bold, italic. No fenced code blocks, inline images, tables, or nested lists.
- An image line `![alt](file)` becomes a `<figure class="figure">`, the image linked to its own file. Image lines with no blank line between them share one `figure row`, side by side, each given a share of the width equal to its aspect ratio (`--ratio`) so they meet at one height; they stack below 34rem. `image_size()` reads the width and height from the file header (PNG, GIF, WebP, JPEG, MP4) into the tag, so nothing moves as images load. Figures sit in the 38rem text column at its full width (they used to step out to 60rem; Jon wanted them in the column), and link to the file for a full-size look. A single image narrower than the column is not stretched past its own width. Consecutive image lines still make a side-by-side row, but at column width a pair gets too small to read, so the project pages don't use them.
- The same syntax with an `.mp4` or `.webm` gives a `<video>` with controls, played on request; the alt text becomes its `aria-label`.
- The same syntax with a `.json` gives a chart (`render_chart()`): the file is inlined into the figure as `<script type="application/json">`, the alt text is its visible title, and `assets/chart.js` draws it in the page's ink with `.switch` buttons for its views and a readout line under it. Two types, both described at the top of `chart.js`: horizontal bars (the default; hollow for the reference, solid for what is tested; hover, focus or a tap on a bar fills the readout), and `"type": "lines"`, an SVG line chart that draws on from the left when it first scrolls into view and on every switch, with a crosshair readout under the pointer or the arrow keys. `chart.js` loads before `app.js` so `fitLabels()` sizes its switch buttons too. A chart must stand alone, with blank lines round it.
- An image with an alpha channel (PNG, or a WebP that isn't animated; `is_ink()`) is taken as a drawing in black ink on a clear ground and gets `class="ink"`, which the dark theme inverts to white ink. The thesis page's plans and section are made this way: greyscale, darkness turned into opacity, RGB zero. The heat-wave-party plan (`11.webp`) also has its two gathering rooms washed in pale blue, cut from the painted ground of the hamlet painting (`09.webp`) and filled to the walls; the dark theme's invert is followed by a 180° hue turn, which leaves grey alone and keeps that wash blue. Photographs and renderings are saved flat, without alpha, so they are left alone. Animated WebPs carry the alpha flag even when opaque, hence the exclusion (Accommodations' opener is one).
- Two files joined by `|` give one picture with a second under it (`render_reveal()`): `![Cool alt | Heated alt](03.webp|03-heat.webp)`. Hovering fades the second in; a tap, click or Enter holds it (`aria-pressed`, set by the last block of `app.js`). Made for the thermochromic paintings, so both files must be the same size.
- **The thesis page** (`taming-torridity/`) uses all three. Its images were cropped from the thesis PDF, the heated paintings cropped to the same box as the cool ones so they register. The paintings are cropped to the wooden board, 3 px inside its edge, with no white paper around them (Jon's call); keep any new painting the same way, and apply one crop to both photos of a pair. `cities.json`, `hamlet.json` and `ground.json` are typed in from the thesis tables and labelled figures (`ground.json` from Figures 64, 65, 68 and 69: annual cooling for one house under six ground-modelling methods, the point of the page's "ground under the model" section, which Jon wants kept prominent). `methods.json` is the same comparison through the power cut, traced from Figures 70–73 (whose embedded titles are right and captions swapped: the plots titled Phoenix are Phoenix). FC factor, Ground Domain and Kiva overlap there and were traced as one bundle, labelled Ground Domain and Kiva; with R10 under the slab every line lies on that bundle, so hidden stretches take its value. `outage.json` was traced from the raster plots of Ground, Shared, Nest and Huddle House (Figures 138, 148, 161, 167; Shared House's two red lines were told apart by weight, solid main house over dashed apartment) by colour, one value an hour; the code-house line, the same in all three, agrees across the traces to 0.1 °C on average, and counting hours over 32 °C from the traces gives back the thesis's own counts within a few hours. The four-city outage plots (Figures 52–55) were tried and could not be traced: eight close colours overlap.
- ` :: ` inside a list item splits it into `.item-main` / `.item-meta` (right-aligned). When *every* item in a list uses `::`, the list gets `class="rows"` and loses its bullets; otherwise it is a normal list. This is what makes the work, CV and contact lists align. The slop list separates with ` - ` instead, so it stays a bulleted list.
- Inline rendering escapes HTML first, stashes code spans and URLs, then applies `--` → en dash and `...` → ellipsis, so those substitutions never touch code or links. External links get `target="_blank" rel="noopener noreferrer"`.
- Wrapped continuation lines (indented or not) are joined into the item above; a blank line ends a list only if the next non-blank line is not another item.

**Template.** `templates/base.html` is plain HTML with `{{placeholder}}` tokens replaced by string substitution in `fill()`, which builds every page, home and project alike. Adding a new site setting means adding both a `{{token}}` in the template and a `page.replace(...)` line in `fill()`. `{{page}}` is `home` or `project`. `{{root}}` is the way back to the top of the site (empty on the home page, `../` on a project page) and prefixes every shared asset, so those links must go through it. On a project page the site name is a link home and the `<title>` is `Project – Site`. `{{tagline}}` and `{{footer}}` are rendered through `render_inline`, so they accept inline Markdown.

**Favicon.** `assets/favicon.ico` (16, 32, 48), `favicon.png` (192) and `apple-touch-icon.png` (180, square corners, since iOS rounds its own) are a white Libre Baskerville roman J on black, linked in the `<head>` of the template. They are PNGs, not SVG, because a favicon can't load the web font: to redraw them, set the J on a canvas in a page that has Libre Baskerville loaded (glyph at 0.78 of the size, centred, 0.05 below the middle; corner radius 0.2 of the size) and build the `.ico` from the 16/32/48 renders with Pillow.

**Theme and font.** An inline script in `<head>` sets `data-theme` (`light`, `dark`, `fun`), `data-font` (`sans`, `serif`) and `data-fun` (`field`, `source`) on `<html>` before first paint from localStorage, falling back to the `_site.md` defaults, which are dark and serif (`auto` follows the OS). `assets/style.css` keys everything off those attributes via CSS custom properties, and includes a print stylesheet.

- The two typefaces share one declared `--step` and `--leading`; the serif is matched to the sans optically with `font-size-adjust` (`--x-height`, set from `--serif-x-height`) so switching does not reflow the page. A `@supports` block restores the old manual size bump where `font-size-adjust` is missing. Buttons need `font-size-adjust` set explicitly, because the browser's button `font` shorthand resets it.
- The switch buttons follow the page face. `fitLabels()` in `assets/app.js` measures every label in both faces once (and again when web fonts finish loading) and fixes each button's `min-width` to the wider, so the controls never shift when the face changes.

**Fun mode.** Everything below lives in `assets/app.js` and the Fun part of `assets/style.css`. None of it prints, and the moving parts sit out under `prefers-reduced-motion`.

- **The colour field.** Five `.blob` pools inside `.blobs > .pools`, each a soft radial of one colour, moved by `place()` on slow Lissajous paths read from one shared clock (not by CSS). Scrolling winds the clock forward, up to about ten times its resting rate, and it decays back. The frame loop (`step()`, started by `wake()`) runs continuously while Fun is on, except on touch, where it sleeps when idle (see **Touch**); if the pools sit still, check that loop, not a keyframe.
- **One hue.** `--c1`..`--c5` are one anchor hue and two neighbours either side, 18° apart, converted from OKLCH so lightness is even round the wheel; `--base` under them is the same hue, pale. The hue starts from the time of day (`HOURS`) and turns as the pointer travels (`SPIN`, degrees per px), so the field is always one analogous family and never averages to grey.
- **Source and Field.** A pill sub-switch (`.fun-controls` inside `.theme-group`) slides in beside the theme buttons in Fun. State is `data-fun` and localStorage `fun-mode` (an old value `cursor` is read as `source`). In `field` the pools show and the pointer clears them to white; in `source` the pools are clipped away, the page stays white, and the pointer lays the colour down. `.pools` is clipped to a circle centred on the button last pressed (`--px`/`--py`), and the clip transitions, so the colour gathers into the button or blooms out of it.
- **The trail.** A `.trail` canvas above the pools. Each mark is kept in a list and redrawn every frame larger and fainter, because it keeps opening out after it is made. Marks are one pre-rendered sprite per colour (`stamp()`), with an edge ramp of seven stops: white in `field`, the hue the mark was made in for `source`. Two things draw: the pointer and the animals. `sow()` takes a source (`{x, y, going, sown}`), a `size` against `HOLE` and a spacing; each mark carries its own `size` and `life`. While an animal is in the air, `trailAnimals()` lays a narrower ribbon (`WAKE`) down its fall and turns the hue by the distance it travels, and when it lands `bloom()` opens one wide, longer-lived mark (`BLOOM`) at the water.
- **The pill.** Its CSS border is transparent (width kept for layout). The outline is `.pill-line`, one closed scalloped path traced just inside the pill by `outline()` (a wave along the normal, a whole number of bumps), drawn once and again on resize or a face change, with `pathLength="1000"`. CSS dashes it 720/280 and animates `stroke-dashoffset`, so three quarters of the line shows and travels round every nine seconds with no script per frame.
- **The thumb.** The pressed side is a `.thumb` under the labels, painted with the live `--c1`/`--c3`/`--c5` gradient, spanning the pill's height and running to the pill's edge on its outer side. `trim()` clips it to `thumbShape()`: the pill's own wave along the top, bottom and outer end, so it meets the line bump for bump, and a phased scalloped cap on the inner end, so there is no seam. `seat()` puts the pressed button's box into `--tx`/`--tw` and, on a switch, the old box into `--fx`/`--fw` (measured before the target moves) and adds `.hop`: the thumb draws in to a circle, the circle crosses, then it opens out. It is re-clipped every frame while hopping and once more on `animationend`.
- **Words.** Every word in `main` is wrapped in a `.shard` span while Fun is on and unwrapped when it is off. Words near the pointer, or near any animal still in the air (`flying`), are nudged with `left`/`top` and eased back by a transition. The shards stay `display: inline` deliberately: `inline-block` would allow rotation, but a browser may break a line between atomic inlines even with a word joiner, which orphaned punctuation after links. Positions are measured once, while nothing is displaced, and again on resize and on a face change.
- **The animals.** A click sends a doodled animal off the pointer: it hops, cross-fades from standing to tucked, spins, falls to the bottom of the window and lands bottom-first, with a wavy water line drawn outward, splash strokes and droplets. The flight time (`--flight`, set inline per dive) grows with the distance to fall, and the splash waits the same. Clicks take turns through ten animals: six share one body and differ in `FACES`, and the camel, giraffe, penguin and hippo have their own `SHAPES`. Every `stroke-width` is scaled by `THIN`, and the `.ink` group is roughened by the `#ink-sketch` filter in the template. `--size` is wired through but fixed at 1.
- **Afloat.** Half a second after landing each animal surfaces as a `.swimmer` along the bottom, backed by a solid shape in `--bg` (`BACKS`) so the one in front hides the one behind. `lineUp()` sets `left`: in the sans a row from the left in landing order, in the serif where each landed. `swim()` adds a `translate` on top: in the serif each roams on its own, rests and sets off again, turned to face its way; in the sans the whole row swims together at `PACE` and turns at the edges. Past forty afloat, the oldest slips away. All of them are cleared when Fun is switched off.
- **Grain and warp.** Grain is `body::after`; a displacement filter sits on `main`.
- **Home page only.** Project pages have no Fun mode. `fill()` sets `data-page` on `<html>` (`home` or `project`); on a project page the head script shows a saved or default `fun` as `light`, without saving it, so the home page is still Fun on the way back, and CSS hides the Fun button and the Source/Field pill. `app.js` needs nothing of its own: with `data-theme` never `fun` there, none of the Fun code starts.
- **Touch.** Under `(hover: none) and (pointer: coarse)` the warp on `main` is dropped and the grain holds still (end of the Fun CSS), and `step()` draws at about 30fps (`FRAME`). The pools have no pace of their own there: `drift` advances only on `rush`, which scrolling and finger travel wind up, so they shift while touched or swiped and then hold still. The loop goes to sleep when `busy()` is false (nothing winding, no trail, no animal in the air or afloat) and `wake()` restarts it; anything new that should move on touch has to call `wake()` and be counted in `busy()`. The finger stands in for the pointer through `touchstart`/`touchmove`, which keep firing while the page scrolls even though the browser cancels the pointer, so the hue follows the thumb, but the finger leaves no trail: on touch only the animals draw. `touchend` lets go. The finger does not push words (`pushers()` skips it on touch), so only animals scatter them. The trail canvas is drawn at 1x and keeps at most 60 marks. Touch `pointerout` is ignored because it fires as soon as a scroll starts. On every device `paint()` skips the canvas when the trail is empty (`drawn`), and `place()` only runs when `drift` has changed.

**Fun mode pitfalls.** Each of these has broken the page silently at least once.

- Keep the `.shard`, `.diver`, `.splash`, `.flicks`, `.drop` and `.swimmer` rules below the field section. Two rewrites of that section swept them away without an error: the spans and figures were still built, they just had no `position` or animation, so nothing moved.
- Never animate in CSS a property that script also sets inline. A filled animation outranks inline style for good: the swimmers' rise once animated `translate`, which `swim()` also sets, so they never swam. The rise uses `transform` now.
- When checking, read rendered geometry (`getBoundingClientRect()`, `getComputedStyle()`), not the inline value just written, and check that a word or animal actually moved rather than that the elements exist.
- The in-app browser preview often stops delivering animation frames while looking live. `requestAnimationFrame` never fires, so the field, the swimming and the fall all freeze. Check whether frames are firing before debugging a "broken" animation there.

**Dev server.** `serve()` has no file watcher. On each request for a page (any path ending in `/` or `.html`) it compares the newest mtime under `content/` (including project folders), `templates/`, and `assets/` to the last build time and rebuilds if newer. Changes to `build.py` itself require restarting the server. Assets are copied flat into `dist/` (no subdirectories); the only subdirectories are the project pages. A `.nojekyll` file is written so GitHub Pages serves the output verbatim.
